Switching & switch-port checks

VLANs, trunks, spanning tree and EtherChannel. It ends with the switch-port check sequence for when a user, phone or uplink "doesn't work".

VLANs and trunks

  • Access port = one VLAN, untagged. Trunk = many VLANs, tagged with 802.1Q (a 4-byte tag carrying a 12-bit VLAN ID).
  • Native VLAN traffic crosses a trunk untagged and must match on both ends (CDP warns on a mismatch). Best practice: use an unused VLAN as native, and prune trunks with switchport trunk allowed vlan.
  • Turn off DTP negotiation on user ports (switchport mode access, switchport nonegotiate on trunks).
  • Inter-VLAN routing: router-on-a-stick (subinterfaces + encapsulation dot1q) or Layer-3 switch SVIs (ip routing).

Spanning tree

  • Prevents Layer-2 loops. Cisco default is Rapid PVST+ (802.1w per VLAN).
  • Root bridge = lowest bridge ID (priority, default 32768 + VLAN ID, then MAC). Set it deliberately: spanning-tree vlan 10 root primary or priority 4096 on the core.
  • Port roles: root, designated, alternate/backup. RSTP states: discarding, learning, forwarding.
  • Edge ports: spanning-tree portfast + spanning-tree bpduguard enable. A BPDU arriving on that port puts it into err-disabled.

EtherChannel

  • Bundles links into one logical link. LACP (802.3ad): active/passive. PAgP (Cisco): desirable/auto. Passive+passive or auto+auto never forms.
  • Member ports must match: speed, duplex, mode (access/trunk), allowed and native VLANs.

Switch-port check sequence

Work it in this order, Layer 1 up. Most "network down" calls end in the first three steps.

  1. Is the port up? show interfaces status. Look for connected / notconnect / err-disabled, and check VLAN, duplex and speed.
  2. Physical errors? show interfaces gi1/0/12. Input errors/CRC mean cabling or a bad patch. Late collisions mean a duplex mismatch. Watch for increasing counters (clear counters first, then recheck).
  3. Err-disabled? show interfaces status err-disabled and show errdisable recovery. Fix the cause (BPDU guard, port security, link flap), then shutdown / no shutdown.
  4. Right VLAN? show vlan brief and show interfaces gi1/0/12 switchport. Check the access VLAN, voice VLAN, and that the VLAN exists and is active.
  5. Is the device seen? show mac address-table interface gi1/0/12. No MAC means the device isn't sending (NIC, cable, or device asleep).
  6. Port security? show port-security interface gi1/0/12. Look at violation count and max MACs.
  7. Uplink side: show interfaces trunk (is the VLAN allowed and forwarding?), show spanning-tree vlan 10 (blocked?), show etherchannel summary (are members bundled with flag P?).
  8. Neighbors: show cdp neighbors / show lldp neighbors confirm what's actually plugged in where.
  9. Power (phones/APs): show power inline gi1/0/12.
